# airlie as a full PWA Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make airlie's web app an installable PWA on Noah's iPhone: a manifest, an app-shell service worker, a sign-in that renews while used, passkey login in the installed app, and Web Push notifications.

**Architecture:** Static files in `web/public` (manifest, icons, `sw.js`) are copied into `src/airlie/serve/web_next` by the Vite build and served at the site root by serve's existing `web_app` handler with `no-cache`. Session renewal goes in serve's `_require_principal` middleware. Push lives in a new `airlie.notify` package: a VAPID key on the host, subscriptions and per-kind settings in the auth store, a sender on httpx, and a notifier that other parts of airlie call; story events are the first source.

**Tech Stack:** Vue 3.5 + Vite 8 + vitest 5 (web), FastAPI + httpx (serve), SQLite (`AuthStore`), `py-vapid` and `http-ece` (new, both on `cryptography`), Playwright e2e suite (`task test:e2e`).

**Spec:** [`docs/superpowers/specs/2026-11-11-airlie-web-chat-agent-design.md`](../specs/2026-11-11-airlie-web-chat-agent-design.md), section "Mobile: a full PWA", phases PWA-a and PWA-b.

## Global Constraints

- Every task passes the gate from the repository root, in order: `uv sync --frozen`, `uv run ruff check .`, `uv run ruff format --check .`, `uv run mypy`, `uv run pytest -q -n auto --maxprocesses 8`, `task web:gate`.
- Unit tests over 500 ms or on the real clock go in `tests/unit/quarantine.toml` with a `slow:` or `clock:` reason.
- Dependencies through uv only (`uv add`); the lock is committed. No Docker.
- The service worker never handles a request whose path starts with `/v1/` or whose `Accept` includes `text/event-stream`.
- Every push shows a visible notification (iOS revokes permission for silent pushes); payloads carry a title, an optional short body, and a link, never chat content.
- The permission prompt is asked only from a tap, never on load.
- Session renewal: when a signed-in request arrives with less than half of `auth.session_days` left, the session is extended to a full `session_days`; a session idle for `session_days` still ends.
- The VAPID contact (`notifications.contact`) is not committed; Noah sets it in `airlie.local.yaml`. Without it push is off and the doctor warns.
- Copy for the offline screen: "Can't reach the Studio". Copy for the update prompt: "Update ready" with a "Reload" button. Copy on iOS outside the installed app: "Add airlie to your Home Screen to get notifications".

## Review Focus

1. **A stale service worker serving an old build after a deploy.** Expected: the new build's `sw.js` installs, the app shows "Update ready", and Reload brings the new assets. Test in Task 2 (`test_new_worker_waits_and_skips_on_message`).
2. **Several requests in flight when the session renews** (the board, the feed, a chat stream). Expected: none of them gets signed out; renewal extends the same token instead of rotating it. Test in Task 3 (`test_renewal_keeps_the_same_token`).
3. **A subscription whose device was reset or whose app was deleted** (push service answers 404 or 410). Expected: the subscription is dropped, other devices still get the push. Test in Task 4 (`test_gone_subscription_is_dropped_and_others_still_send`).
4. **The live feed (`GET /v1/events`, a long SSE stream) through the service worker.** Expected: it is never intercepted or cached. Test in Task 2 (`test_api_and_event_streams_pass_through`).
5. **Signing out on one device.** Expected: that device's subscription is removed before the session ends, and the other devices keep theirs. Test in Task 7 (`signOut removes this device's subscription`).

  - `Notifier(store: AuthStore, sender: PushSender | None, default_kinds: Sequence[NotificationKind])` with `async notify(user_id: str | None, kind: NotificationKind, title: str, url: str, body: str | None = None) -> int`: sends `{"title", "url", "body"?}` to every subscription of `user_id` (every person's when `None`) whose person has `kind` on (their setting, else `default_kinds`); drops a subscription answered 404 or 410; returns the count sent; returns 0 when `sender` is `None`.
