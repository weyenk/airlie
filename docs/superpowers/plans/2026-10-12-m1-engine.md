# M1 Managed vllm-mlx Engine Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** `task up` starts vllm-mlx from `airlie.yaml` with the preloaded models resident, airlie talks to it through
one `Engine` seam, and `task bench` prints real throughput numbers plus the tool-stall resume cache-hit rate.

**Architecture:** `Engine` protocol → `HTTPEngine` (OpenAI-compatible streaming client over httpx) → a vllm-mlx
process that `EngineProcess` starts from a generated `--models-config` registry. `FakeEngine` is the test double
for every later milestone. Nothing in airlie imports `vllm_mlx`, `mlx` or `mlx_lm`.

**Tech Stack:** httpx (HTTP/2, SSE), psutil, typer, pytest with `httpx.MockTransport` fixtures recorded from a real
vllm-mlx run.

**Spec:** `docs/wiki/build-spec/02_vllm_mlx_engine_and_uma_execution_spec.md` §1 (launch parameters, 8080,
127.0.0.1, `--max-num-seqs 16`, `--prefill-step-size 2048`, prefix caching), `01_…` §2 (HTTP/SSE OpenAI link),
`04_…` §2 (zero-overhead resume after a tool stall).

## Global Constraints
- Engine endpoint `127.0.0.1:8080`; flags from spec 02 §1 plus `--continuous-batching` (vllm-mlx 0.5.0 spelling:
  `--enable-prefix-cache`, default on).
- Weights are loaded by the pinned revision's snapshot path, never by repo name, so `--offline` is safe.
- No `vllm_mlx` import in `src/airlie`.
- Every subprocess call goes through an injected runner so unit tests never start a server.

## Review Focus
1. SSE streams that end without `[DONE]` or with an error frame mid-stream must raise `EngineError` with the partial
   text, not hang — `test_http_engine_stream_error_frame`.
2. A registry model still loading (`/health` ok, model absent from `/v1/models`) must be reported as `loading` by
   `task status`, not `ok` — `test_status_reports_loading_model`.
3. `cancel` must close the HTTP stream so the server frees the batch slot — `test_cancel_closes_stream`.
4. Prefix-cache hit on turn 2 after a tool result must be measured, not assumed — `bench --resume` reports
   `cached_tokens` and a hit rate; fixture test `test_bench_resume_counts_cached_tokens`.
5. A port already in use by a non-airlie process must fail `task up` with the pid of the holder —
   `test_up_refuses_busy_port`.

### Task 1: Engine types, protocol, FakeEngine

**Files:** Create `src/airlie/engine/__init__.py`, `types.py`, `protocol.py`, `fake.py`; Test `tests/unit/test_fake_engine.py`.

**Produces:**
```python
Message(role: Literal["system","user","assistant","tool"], content: str, name: str | None = None,
        tool_calls: list[ToolCall] | None = None, tool_call_id: str | None = None)

GenRequest(role, messages, sampling, max_tokens, stop, tools=None, thinking=None, request_id=uuid)
TokenEvent(text: str, reasoning: bool)
GenResult(text, reasoning, tool_calls, finish_reason, prompt_tokens, completion_tokens, cached_tokens,
          accepted_draft_tokens, ttft_ms, decode_tps, raw_finish: str)

EngineStats(requests: int, tokens_out: int, errors: int)
class EngineError(RuntimeError)
class Engine(Protocol): capabilities; start(); stop(); health(); generate(req, on_token=None); cancel(request_id); yes_no(role, messages); stats()
FakeEngine(scripts: dict[str, list[FakeReply]] | None)   # per role queue; FakeReply(text="", reasoning="", tool_calls=[], p_yes=None, cached_tokens=None)
```

      word; `yes_no` returns `(p_yes, 1-p_yes)` from the script; unknown role raises `EngineError`.

       "--prefill-step-size",…,"--gpu-memory-utilization",…,"--max-request-tokens",…,"--timeout",…,
       "--enable-auto-tool-choice","--tool-call-parser",<from the preloaded team model>,"--reasoning-parser",…,
       "--offline", *extra_args]` (+ `--continuous-batching` when engine default is on, `--kv-cache-quantization` when set).
      Tests pin the exact argv for the default config.
- [ ] `process.py`: `EngineProcess(spec, state_dir, runner: ProcessRunner)`; `start()` (refuse if pidfile alive or
