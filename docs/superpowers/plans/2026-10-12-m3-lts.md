# M3 Learning-to-Share Substrate Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** With `--k 3`, teams admit steps into the shared memory bank and fetch other teams' values; `task memory
-- RUN_ID` shows the bank with cross-team access counts; every admission decision and retrieval is logged in the
schema M5's trainer consumes.

**Architecture:** `SharedMemoryBank` + `MemoryEntry` exactly as spec 03 §1. Each team step (u_t, o_t) goes
through `Summarizer` → `LTSAdmissionController.decide` → bank. Before every model call the team's prompt gets the
spec 04 §3 block `[Shared Memory Keys Available]:` with `- Key [id]: summary` lines (bounded by `lts.max_keys`), and
a `retrieve_value(entry_id)` tool returns the full value (spec 01 §4 step 7). Controllers: `always` (the spec
blueprint's `return True`), `never` (baseline), `heuristic` (named predicates), `judge` (`Engine.yes_no`).

**Spec:** `docs/wiki/build-spec/03_…` §1 (data structures), `04_…` §3 (injection format, `run_step`,
`evaluate_lts_admission`), `01_…` §4 steps 5–7.

## Global Constraints
- Class and method names verbatim: `MemoryEntry{id, team_id, step_num, summary_key, raw_value, timestamp,
  access_count}`, `SharedMemoryBank.add_entry / get_summaries / retrieve_value(entry_id, requesting_team_id)`.
- `retrieve_value` increments `access_count` only for cross-team reads.
- Injection text starts with `\n[Shared Memory Keys Available]:\n` and lists `- Key [<id>]: <summary_key>`.
- Prompts stay prefix-stable: keys are appended as a new message, earlier messages are never edited.

## Review Focus
1. Admission flood: `always` with `lts.max_keys: 2` injects at most 2 keys — `test_inject_bounded_by_max_keys`.
2. Unknown entry id → `None` from `retrieve_value` and a clean tool observation — `test_retrieve_unknown_id`.
3. Concurrency: K teams adding entries at once never lose or duplicate ids — `test_bank_concurrent_adds`.
4. A team must not see its own key injected as "new" forever — keys are listed once per step, newest first.
5. Logs must carry everything M5 needs (`query, memory_keys, u_t, s_t, o_t, decision, p_yes`) —
   `test_admission_log_schema`.
