# Web App v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A chat-first web app served by `task serve`: sign in with the serve key, chat with the chief, start and follow jobs, and (once the local board PR lands) work the board.

**Architecture:** Static files under `src/airlie/serve/web/` mounted by FastAPI at `/` with no bundler: ES modules, one stylesheet with the mockups' tokens, a tiny router. Three new read endpoints give the app its lists. Chat streams from the existing `/v1/chat/completions`.

**Tech Stack:** FastAPI `StaticFiles`, vanilla ES modules (no framework), CSS custom properties for dark/light, pytest + `TestClient` for the Python side.

**Spec:** `docs/superpowers/specs/2026-10-17-web-app-and-local-board-design.md` (sections "Serving" and "The app's screens"). Mockups: https://claude.ai/artifact/DfBHBeXP356eFkFSgEZCqP.

## Global Constraints

- No node toolchain, no bundler, no framework; scripts and styles are files under `src/airlie/serve/web/`; no CDN at runtime (the app must work on the tailnet with no internet). Fonts: system stack (the mockups' IBM Plex is optional and must not be fetched from the network).
- The key middleware guards `/v1` only; static files are public.
- Every screen works at 390 px wide: a bottom tab bar on phones, the top nav on desktop.
- Dark theme by default, light via a toggle stored in `localStorage` (`airlie.theme`); tokens as in the mockups (dark bg `#000`, surface `#0E1013`, accent `#8FB6E0`; light bg `#F6F5F1`, accent `#0B5F7A`).
- Tests: Python routes only; no live engine; `task check` passes. Commits end with `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`.
- The Board screen is built against the `/v1/board` API from the local-board plan; if that PR is not merged yet, build the screen against the documented routes and mark it "needs the board PR" in the PR body.

## Review Focus

- A 401 from any `/v1` call must send the user to Sign in and keep the message they typed (not lose it). (Task 5 by hand; Task 2's `test_static_shell_is_public_but_v1_needs_the_key`.)
- A job that ends with `state: failed` must show the error text, not spin forever. (Task 6: `test_jobs_list_includes_failed_state_and_error`.)
- A chat stream that stops mid-reply (engine down) must show what arrived plus "airlie stopped answering", not a blank bubble. (Task 5 by hand; the stream parser's test with a truncated SSE body in Task 5.)
- `GET /runs` must tolerate a run directory with no `events.jsonl` or a torn last line. (Task 3 tests.)
- The repository picker only offers paths serve can see (`story.repo` and clones under `story.repos_root`), never free text, since `POST /runs` takes a path on the Studio. (Task 3's `GET /repos`.)

### Task 2: Sign in and the API client

**Files:**
- Create: `src/airlie/serve/web/api.js` (`getKey()`, `setKey()`, `clearKey()`, `request(path, {method, body})` adding the Bearer header, throwing `AuthError` on 401; `stream(path, body, onDelta)` reading an SSE `text/event-stream` body and calling `onDelta(text)` per `data:` chunk's `choices[0].delta.content`, resolving on `[DONE]`, rejecting with `StreamCut(partial)` if the body ends without `[DONE]`)
- Create: `src/airlie/serve/web/screens/signin.js` (the phone sign-in mockup: key field, Sign in, error text "That key isn't valid. Ask Noah for a new one.", the Tailscale hint)
- Modify: `app.js` (a hash router: `#/` chat, `#/jobs`, `#/jobs/<id>`, `#/board`, `#/signin`; redirect to `#/signin` when no key or on `AuthError`)

- [ ] **Step 1**: build; sign-in checks the key with `GET /v1/models` (a 401 shows the error, a 200 stores the key and goes to `#/`).
- [ ] **Step 2: Check by hand**: `task serve -- --api-key k`, open http://127.0.0.1:8090/, wrong key → error, right key → chat shell. **Step 3: Commit** `feat(web): sign-in and API client`.

### Task 6: Start work, follow a job, approve a plan

**Files:**
- Create: `src/airlie/serve/web/screens/jobs.js` (list from `GET /v1/airlie/jobs`, plus `GET /v1/airlie/stories` and `GET /v1/airlie/runs` as "Recent results")
- Create: `src/airlie/serve/web/screens/job.js` (one job: long-poll `GET /v1/airlie/jobs/{id}?since=&wait=20`; the agent tree from events: `plan` → nodes per subtask, `subtask_start`/`subtask_done` → active/done, `review` → the reviewer node, `step` → the selected node's latest steps; Stop → `DELETE /v1/airlie/jobs/{id}`)

- Modify: `chat.js` (a started job renders an inline job card linking to `#/jobs/<id>`)
