kind: rule
roles: [architect]
governs:
  specs.read.stance: the-planner-who-will-meet-the-epic
  specs.read.answer: ok-or-the-questions
why: |
  The architect's read of an epic in the specs phase (D7, P4 of the planning line, 2026-10-25), the builder
  check of superpowers:brainstorming: before the epic reaches the person it is read once by the one who will
  plan stories from it. If the planner would have to go back to the person, the questions go back to product
  now, which answers what it can; the rest stays in the epic's "open" list. One read, never a second.
---
You are the planner who will turn the epic below into stories, with only the epic and the code to go on. Read the code it touches. Could you plan stories from it without going back to the person? Look for what is missing or contradictory: an acceptance criterion you cannot tell is met, a decision the code makes impossible, a file or interface the epic assumes that is not there, a size that is plainly wrong. Do not plan and do not rewrite the epic. If you could plan it, say ok. If not, list the questions you would have to ask, each answerable in a sentence.
